# invader decisions

What invader is for, what must stay true, and what is decided and why. When a question comes up, this page answers it. Changing a decision here is a deliberate act, not a side effect of a task. How each thing works, as someone using it sees it, is in [README.md](README.md); how it is built is in [plumbing.md](plumbing.md).

## What it is

**North star:** invader puts any folder of your real files, a checked map of how they connect, and your coding agent's terminal in one window, with your kit on hand for you and the agent. The agent does the understanding and the writing; invader checks its map against the disk, shows live where it is working, shows what the agent is told, and lets you edit Markdown by hand.

The window answers three questions about the open folder, in plain words:

1. **What is here?** The tree, and the map, checked against the disk.
2. **What is the agent told here?** Its instructions, settings and permissions, what it runs on its own, its connections, skills, commands and helpers, wherever they live.
3. **Where did I leave off, and what is the agent doing now?** The branch, what changed, the last commits, and live marks on what the agent is changing.

The workspace I could not find. I build software with AI coding tools and I do not come from engineering. VS Code is built for engineers and assumes I know what I am looking at. The simple tools hide the real files. invader sits between them: my real files, shown in plain words, with the coding agent working in the same window, so I can see, understand, navigate and work in what I am building without getting lost.

It is for me first, and open source for people like me. I build faster than I understand, and I lose track of what exists, how it connects and what the agent just did. It stays small enough that I can explain every commit.

alabs was the first attempt. It is inspiration, not a spec. It is not pulled: it becomes invader.

## What must stay true

- **The files are the truth.** No private formats. Anything that matters, maps included, is a file I can open without the app.
- **Maps are checked against the disk.** Every box points to real files, and every arrow is backed by real text in a real file. Missing information beats false certainty.
- **Content is data.** Opening, reading or drawing a project never runs it. The only thing that runs is what is typed into a terminal, and the page a server I started there serves, when I open it in the preview, in a view of its own apart from the window.
- **Local.** No accounts, cloud, telemetry or hosted backend.
- **Connect, don't rebuild.** Git keeps history, the terminal runs commands, Claude Code and Codex write code. invader shows what they do and makes it understandable.
- **Fast, and nothing behind my back.** Normal use never waits. Anything the app does on its own, like watching the folder, is visible.

What these mean for the code, file by file, is in [plumbing.md](plumbing.md#what-it-reads-writes-and-runs).

## The daily loop

1. I open invader. It shows the folder its terminal is in, with the tabs I left there: the map or README first, and under it what happened here, the last sessions and commits. The branch and what changed are in the status strip, and what the agent is told is one click away.
2. In the terminal I run `claude` or `codex` and ask for a change.
3. While the agent works, the files it is changing are marked in the tree and on the map. I click one and read it as it is now.
4. When the project has a web page, I start its dev server in a second terminal (⌘T) and open its address in the preview, and try what the agent changed there, going back and forth to the files.
5. When I lose track of how it fits together, I press **Build map** or **Update map**, read the request and press Enter. The agent writes the map; invader checks it.
6. I read, understand and decide. Where a Markdown file needs a small fix, I make it by hand; anything else I ask the agent for. I commit in the terminal, or ask the agent to.

## Decisions

Each row says what was decided, when, and why. What it looks like in use is in [README.md](README.md).

| Question | Decision |
| --- | --- |
| Who it is for | Me first, and people like me who build with AI without an engineering background. Never teams, companies or enterprise. |
| Name | invader, everywhere, including `package.json` and the dock name `npm install` sets. The rocket icon fits it. This copy, next-invader, runs as next-invader (`productName` and the dock name) so it keeps its own memory apart from invader's; decided 2026-09-24, because the two shared one `state.json`. |
| Stack | Electron. `npm run app` builds `next-invader.app` for this Mac only, signed ad hoc, so it opens from the Finder or the Dock with no terminal behind it; it is not installed, published or updated by itself. Decided 2026-09-24, in the daily-workspace pass: I should not need `npm start` to use my workspace. |
| What it shows | The folder the chosen terminal is in, and it follows when that terminal moves: when I `cd` in it, or ⌘O moves it. A terminal I have not chosen never moves the window, and each keeps its own folder (decided 2026-09-24, with several terminals). Any folder can be opened, and any folder of files works, not only repositories. It aims at the popular stacks that people like me, building with AI without an engineering background, actually use. |
| The coding tool | Real terminals inside the window (node-pty and xterm.js). `claude` or `codex` run there as they would anywhere. No model is built into the app. From 2026-09-24 there can be several, as tabs, each with its own shell, and none is started again after quitting. Decided in the build–run–see pass: I leave the agent running in one terminal and my dev server in another. |
| Preview | Added 2026-09-24, in the build–run–see pass, so I can use my app beside its files. A **preview** tab shows a page served on this computer, and nothing else: I start the server myself and give its address; nothing is scanned, guessed or started. The page is not trusted: it runs in a view of its own, with none of the window's bridge, and anything that leads off this computer is offered to the browser, opened only when I click. A certificate a local https server made itself is not accepted just because the address is local: I may trust it until the app quits (decided in the daily-workspace pass). |
| Changed files | Listed on the changes page, from the open folder's Git status plus a watcher. The tree and the map stay plain to work in: they mark only what changed in the last few seconds, and what a replay has changed so far (moved off them late on 2026-09-23: the marks everywhere drew my eye away from working). No line-by-line diffs. The list puts each file under the one of the last sessions that changed it, so before committing I see which agent did what. Decided 2026-09-23. |
| Editing | I edit raw Markdown by hand in the app, and Save writes it to the real file. Everything else is the agent's job. This is a deliberate change, made 2026-09-23; until then the app wrote nothing into the folders it shows. From 2026-09-24 an edit not saved is dropped only when I say so: it stays with its file while I look at other tabs, and nothing is written over a file that changed under it until I choose. Also from 2026-09-24, in the daily-workspace pass: a moment after I stop typing, the edit is kept in the app's own data folder, never in my folders, and comes back when its folder opens again after a quit, a crash or a switch; only Save writes the file, and nothing is dropped to make room. Quitting asks once, about the edits and the terminals together. |
| kit | Optional: invader works the same without one. A kit is what I want the agent to know about me that it cannot know on its own. When the agent needs to know something about me, it looks in the kit first: if it is there, it keeps going; if not, it asks me. The invader repository ships a blank `kit/` holding only a README that says what a kit is and how to make your own. My own kit lives at `~/kit`, outside every repository, and invader keeps it in reach from whichever folder is open, under the tree, apart from the open folder (moved there from above the tree on 2026-09-23, with the tabs). The place is fixed, with no setting; decided 2026-09-23. invader affects an agent only when the agent is pointed at it: a line in the agent rules of the project I am working on sends it to the kit, and nothing outside invader is changed to do it. The agent's own instructions may overrule that; that is accepted. My personal context never goes into the invader repository. |
| Outside the open folder | Nothing leads outside the open folder, except four deliberate loosenings, all made 2026-09-23. First my kit at `~/kit`. Then, that evening, the agent setup page: it reads, and never writes, the files that tell claude and codex how to behave in the open folder, wherever they are, and hides secrets in what it shows. Then, that night, the last sessions: invader reads, and never writes, the records claude and codex keep of their sessions in the open folder, and passes on only the few facts the summary shows, and, to replay one or to outline what one does as it runs, when each step happened and which files in the open folder it touched. And checking whether a path a Markdown file names exists: it asks only whether it is there. |
| Git | Read to mark changes and to show the last few commits. Commits happen in the terminal. |
| Where I left off | Opening a folder, or clicking its name, shows its map or README first, so the page is a place to work, and under it what happened there: the last claude and codex sessions, the last commits, and the Markdown that points at nothing. The branch and how much changed are in the status strip, and what the agent is told is the **agent setup** row, so the page does not repeat them. Sessions come from the records claude and codex keep themselves; invader only reads them, and nothing is stored. Files a shell command names as what it writes count as changed from 2026-09-23, since Codex desktop writes whole projects that way. Decided 2026-09-23, in the rebuild; sessions added the same night, from the Claude.ai findings (I could not rebuild what a session did). Moved under the map or README late that night: with the summary on top, the page read as a report of what had happened, not a workspace. |
| Tabs | The middle has tabs, as alabs had: **Overview**, the folder's own page, first and always there, then a tab for each file, folder or page I open, until I close it. Added late on 2026-09-23, when moving around felt clunky. |
| Every folder is a map | Clicking a folder opens it as a map I can walk into, as entering a place did in alabs. A folder with a `map.json` shows it; any other is drawn from the folder, never written. Going from folder to folder stays in one tab, with a trail back up. Decided 2026-09-24: a folder without a map felt like a dead end. |
| Coming back | Quitting and opening again puts me back where I was: the folders, their tabs, the window and the layout, kept in `state.json` in the app's own data folder, never in my folders, and checked when read back. Only the view comes back: files are read again, one new shell starts, and the preview waits for Load; nothing is run again. Decided 2026-09-24, in the usability pass: every return meant building the workspace again. Later that day, each open tab's place came back too, and unsaved edits, as under Editing; no history of where I went, and nothing typed or run in a terminal. |
| Getting around | Every pane can be reached by keyboard, from a real menu whose keys work even in the terminal, and the lines between the panes can be dragged. No key reloads the window; ⌘R reloads only the page in the preview. Decided 2026-09-24, in the usability pass. Keys that act on what is shown act where the keyboard is, and every other key goes to the terminal as it is. Decided in the daily-workspace pass. |
| Following the work | Every place is a file and a line, like `src/app.js:12`, and the tree, the map, the tabs, search and the terminal all go to one the same way: the file's tab, at that line. Back and forward go where I was reading, and none of it is written anywhere. Copy reference puts `path:line` on the clipboard for me to paste into the terminal or a prompt; nothing is typed into the terminal for any of this. A path a terminal prints opens only when main finds it in the open folder or the kit, read from the folder that terminal was in. Since a command can print a path from another folder, the shell's folder is not proof: a relative path opens directly only when it is the one file here by that name, and otherwise invader asks which (changed in the daily-workspace pass: two files with one name opened the wrong one). Nothing is guessed. Decided 2026-09-24, in the connected-workspace pass: I kept losing my place and copying paths by hand. |
| Search | Came in on 2026-09-24, taken out of Not now. Find in Folder reads the open folder's files, not the kit, only when I ask, and keeps nothing: no index, no model. Find in File finds in what the middle shows. |
| Replay | Each of the last sessions can be replayed, step by step from its record, on the map, or on the tree when there is no map. A timeline goes to any step (added the same night: a session of hundreds of steps was too long to step through, and I could not see where the work was). It works for sessions run anywhere, in the Claude and Codex apps too, in folders without Git, and long after the live marks have faded. The window gets only the times and the file names, never the conversation or the commands. Decided 2026-09-23, when invader's next direction was chosen: the live marks show only what happens while I watch, and I mostly run agents outside invader. |
| The agent's trail | While claude or codex works in the open folder, in invader's terminal or in its own app, what it reads is outlined for a few seconds, as a replay outlines it, and the status strip says what its newest step did. It comes from the same records as replay, and the window gets the same: when, which files, never the conversation. Decided 2026-09-23: while the agent only reads, nothing moved, so the first minute of every change looked idle. |
| Pasting into the shell | When the shell itself is in front, a paste of more than one line, or of a line starting with a copied prompt, asks first, and nothing is pasted until I choose. Pastes into claude, codex or any other program go straight in. Decided 2026-09-23, in the rebuild, from the Claude.ai findings (a pasted "expected output" block became a wall of errors). |
| Links to nothing | The open folder's own page lists the files whose Markdown points at nothing. Projects get renamed and moved, and these go stale without a sound. Paths written out under the agents' own folders are left out: files there are optional, a note naming one usually describes it, and the agent setup page shows what is there. To find them, invader asks whether each named path exists, even outside the open folder; it never reads or shows what is there. Decided 2026-09-23, in the rebuild, from the Claude.ai findings (four renames, a map format documented outside its folder, a command with a path that broke). |
| Agent setup | A page listing what claude and codex are told when they start in the open folder, wherever it lives: whose each thing is, how far it reaches and where it lives, and at the top how much each agent reads before I type. Files outside the open folder open read-only with secrets hidden. It never changes anything: to change the agent's setup, I ask the agent or edit the file. Decided 2026-09-23, in the rebuild, from what cockpit-v2 showed; the count added the same night, from the Claude.ai findings (rules for one kind of work reaching every folder, and connections loading before a session starts). |
| The map file | One `map.json` in the folder it describes, in a small shape of groups, boxes and arrows, settled 2026-09-22 and written out in [README.md](README.md#the-map-file). The agent writes it; invader only checks it and draws what holds. |
| Building maps | A **Build map** / **Update map** button types a ready-made request into the `claude` or `codex` already running in the terminal, with what invader dropped and why. I press Enter and the agent writes `map.json`. invader never starts an agent, calls a model or writes a map. When it cannot tell which terminal, it asks instead of guessing (daily-workspace pass). |
| Going public | Decided 2026-09-23: invader goes public now as the new version of alabs, open source on GitHub under my name at `dan-sheehan/invader`. alabs is not pulled: the repository is renamed from alabs to invader, which keeps its stars and redirects old links, and its `main` is replaced by one fresh commit signed with my GitHub no-reply address. The old alabs stays at its `v0.1.0` tag. The public copy lives in its own folder; the earlier copies stay frozen as private records. Pushing is public, so the agent asks me first. |
| Model benchmarks | `npm run bench` runs `claude`, `codex` or `opencode` with a chosen model, with nobody at the keyboard, on invader's own work in a throwaway copy at a fixed commit, and scores it with checks that need no judgment. I run it by hand; the app never does, and still never starts an agent or calls a model. Only that copy of invader's code goes to the model. Decided 2026-09-23, the day a free stealth model came out: to see whether a new model can do my daily work before I use it. |
| Documents | Names in capitals (`README.md`, `HARNESS.md`, `CLAUDE.md`, `AGENTS.md`) are for someone else to read: people using invader, or agents working on it. Lowercase names (`decisions.md`, `plumbing.md`, `design.md`) are what I keep about the project for myself; agents read them too. Each fact has one home, listed in [HARNESS.md](HARNESS.md#documents). Decided 2026-09-25, in the documentation pass. |
| Success | I work in it every day instead of beside it. |

## Not now

These come in when I notice I need them: editing anything but Markdown, editing the agent's setup from the setup page, a plain-words note on what a file or folder is for (`package.json`, `node_modules/`, `.gitignore`). Outside connections, and a safe version with a playground to try changes in, come later. A live activity feed was tried in a mockup and left out as too busy.

## What cockpit-v2 taught

cockpit-v2, built 2026-09-11, was a read-only window onto the hidden Claude Code and Codex setup on this computer. It is where invader started.

Keep: much of what shapes the agent sits in hidden files, and seeing them in plain words, with exact paths, is worth a page. Read-only. Secrets hidden in what is shown. Scan when asked, store nothing.

Drop: the planner, builder and reviewer relay, the plans folder and the pile of process documents. A separate app for it: the setup matters where the work happens, in the folder that is open.

## What alabs taught

Keep: checked maps, the dark thin-line look, content is data, files are the truth.

Drop: the second runtime, the glossary and metaphor words, the creature framework, the pile of rule documents.
